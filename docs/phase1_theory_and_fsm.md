# Phase 1: Theory of Computation (TOC) Formalization & Protocol FSM Specification

## 1. Mathematical Formalization of the Protocol FSM

According to Automata Theory, the network protocol state machine is modeled as a **Deterministic Finite Automaton (DFA)**:

$$M = (Q, \Sigma, \delta, q_0, F)$$

Where:
- **$Q$ (Finite Set of States)**:
  $$Q = \{\text{CLOSED}, \text{LISTEN}, \text{SYN\_SENT}, \text{SYN\_RCVD}, \text{ESTABLISHED}, \text{FIN\_WAIT\_1}, \text{FIN\_WAIT\_2}, \text{CLOSE\_WAIT}, \text{LAST\_ACK}, \text{TIME\_WAIT}, \text{ERROR\_STATE}\}$$
- **$\Sigma$ (Input Alphabet / Protocol Events)**:
  $$\Sigma = \{\text{LISTEN}, \text{SYN}, \text{SYN\_ACK}, \text{ACK}, \text{DATA}, \text{FIN}, \text{RST}, \text{TIMEOUT}\}$$
- **$q_0$ (Initial State)**:
  $$q_0 = \text{CLOSED}$$
- **$F$ (Accepting / Clean Termination States)**:
  $$F = \{\text{CLOSED}, \text{TIME\_WAIT}\}$$
- **$\delta$ (State Transition Function)**:
  $$\delta: Q \times \Sigma \to Q$$

## 2. Formal Transition Table $\delta(q, \sigma)$

| Current State ($q$) | Input Symbol ($\sigma$) | Next State ($\delta(q, \sigma)$) | Description / RFC 793 Semantics |
| :--- | :--- | :--- | :--- |
| `CLOSED` | `LISTEN` | `LISTEN` | Passive open (Server binds to socket) |
| `CLOSED` | `SYN` | `SYN_SENT` | Active open (Client sends SYN) |
| `LISTEN` | `SYN` | `SYN_RCVD` | Server receives SYN, replies with SYN-ACK |
| `SYN_SENT` | `SYN_ACK` | `ESTABLISHED` | Client receives SYN-ACK, completes handshake |
| `SYN_SENT` | `SYN` | `SYN_RCVD` | Simultaneous connection open |
| `SYN_RCVD` | `ACK` | `ESTABLISHED` | Server receives ACK, connection established |
| `ESTABLISHED` | `DATA` | `ESTABLISHED` | Bidirectional full-duplex payload transmission |
| `ESTABLISHED` | `ACK` | `ESTABLISHED` | Piggybacked or standalone acknowledgment |
| `ESTABLISHED` | `FIN` | `FIN_WAIT_1` | Active close initiated; FIN sent |
| `FIN_WAIT_1` | `ACK` | `FIN_WAIT_2` | Remote peer acknowledged active close |
| `FIN_WAIT_2` | `FIN` | `TIME_WAIT` | Remote peer sent its FIN |
| `TIME_WAIT` | `TIMEOUT` | `CLOSED` | 2MSL timer expires; socket returns to idle |
| `ESTABLISHED` | `FIN` (rx) | `CLOSE_WAIT` | Passive close: remote peer closed |
| `CLOSE_WAIT` | `FIN` | `LAST_ACK` | Application closes; sends final FIN |
| `LAST_ACK` | `ACK` | `CLOSED` | Final ACK received; connection closed |
| *Active States* | `RST` | `CLOSED` | Abrupt connection termination |
| **Any Undefined $(q, \sigma)$** | *Any* | `ERROR_STATE` | **Intrusion / Protocol Anomaly Flagged** |

## 3. Chomsky Hierarchy & Regular Grammar Representation

Because the protocol sequence is recognized by a DFA, the legitimate protocol language $L(M)$ is a **Type-3 (Regular Language)**.

It can be generated by a **Right-Linear Regular Grammar** $G = (V_N, \Sigma, P, S)$:
- Non-terminals $V_N = Q$
- Terminals $\Sigma$
- Start symbol $S = \text{CLOSED}$
- Production Rules $P$:
  $$\begin{aligned}
  S &\to \text{SYN} \cdot A \mid \text{LISTEN} \cdot B \\
  A &\to \text{SYN\_ACK} \cdot C \\
  B &\to \text{SYN} \cdot D \\
  D &\to \text{ACK} \cdot C \\
  C &\to \text{DATA} \cdot C \mid \text{ACK} \cdot C \mid \text{FIN} \cdot E \mid \text{RST} \\
  E &\to \text{ACK} \cdot F \\
  F &\to \text{FIN} \cdot G \\
  G &\to \text{TIMEOUT} \mid \epsilon
  \end{aligned}$$

### Complement Language (The Anomaly Space)
An intrusion detection system using formal automata exploits the theorem that **regular languages are closed under complementation**:
$$L_{\text{anomaly}} = \Sigma^* \setminus L(M)$$
Any sequence $w \in L_{\text{anomaly}}$ contains at least one symbol $\sigma_k$ such that $\delta(q_{k-1}, \sigma_k) = \emptyset$, driving the automaton into `ERROR_STATE`.

## 4. Attack Signature to FSM Mapping

| Attack Vector | Attempted Transition $(s_t \xrightarrow{e} s_{t+1})$ | Expected RFC Grammar | Severity | Alert Attribution |
| :--- | :--- | :--- | :--- | :--- |
| **Out-of-Order ACK Injection** | `CLOSED` $\xrightarrow{\text{ACK}}$ Anomaly | Must receive `SYN` first | Critical | CWE-940: Blind ACK Injection / State Desync |
| **Premature Payload Injection** | `CLOSED` $\xrightarrow{\text{DATA}}$ Anomaly | Must establish 3-way handshake | Critical | CWE-345: Unauthenticated Data Injection |
| **Stealth FIN Scan** | `CLOSED` $\xrightarrow{\text{FIN}}$ Anomaly | Port scanning technique | High | MITRE ATT&CK T1595: Active Reconnaissance |
| **Aborted Handshake Probe** | `SYN_SENT` $\xrightarrow{\text{FIN}}$ Anomaly | Expects `SYN_ACK` | Warning | Handshake probe / DoS probe |
| **Volumetric SYN Flood** | Rapid `CLOSED` $\xrightarrow{\text{SYN}}$ loops without ACK | Handshake stalled in `SYN_RCVD` | High (ML) | Grammatically valid step, but statistically anomalous (detected via ML/Hybrid in Phase 3) |
